## 1. Goals

- Fix the unhandled traceback (`ValueError: Empty ticker name` and `AttributeError`) that occurs when running `uv run yfinance history` or `uv run yfinance lookup` without providing any identifier arguments.
- Ensure the CLI provides a friendly, descriptive error message instead of crashing.

## 2. Work Done

- Analyzed `src/py_yfinance/cli.py` to understand the `LookupCommand` and `HistoryCommand` argument definitions.
- Updated `LookupCommand.cli_cmd()` to check if any of `--isin`, `--symbol`, or `--ticker` are present before proceeding with resolution.
- Updated `HistoryCommand.cli_cmd()` to consistently check for the presence of an identifier, properly referencing `--symbol`, `--ticker`, or `--isin`.
- Handled the missing arguments by emitting a `logger.error` message and gracefully terminating with `sys.exit(1)`.
- Added new test cases `test_lookup_command_no_identifier` and `test_history_command_no_identifier` in `tests/test_cli.py` to ensure the new behavior is covered.
- Ran `uv run pytest` to verify the new tests pass and ensure no regressions were introduced.

## 3. Decisions Made

| Decision | Rationale |
|----------|-----------|
| Add manual identifier validation | The underlying `yfinance` library or Pydantic setup lacked strict constraints for these fields to be mutually exclusive but required. Manual validation at the CLI level intercepts the missing state early. |
| Exit with `sys.exit(1)` gracefully | Providing a targeted log error message and exiting with `1` adheres to standard CLI usability principles without confusing users with full stack traces. |
