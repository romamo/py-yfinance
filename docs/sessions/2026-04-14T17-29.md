## 1. Goals

- Troubleshoot and fix the unrecognized `--symbol` argument in the CLI.
- Enhance the CLI to support `--symbol` as an alias for `--ticker`.
- Migrate the project to `pydantic-market-data` 0.2.0, applying all breaking changes from its migration guide.
- Fully remove backward compatibility (the `--ticker` alias) as requested.

## 2. Work Done

- Added an alias for `--symbol` to `--ticker` in `SearchArgs` and `HistoryArgs` usage via `AliasChoices` in Pydantic.
- Updated `pydantic-market-data` to version `0.2.0` via `uv`.
- Migrated `src/py_yfinance/source.py` and `src/py_yfinance/cli.py` to use `Symbol` (instead of `Ticker`) and `Security` (instead of `Symbol`).
- Updated `PriceVerificationError` to use `symbol=` instead of `ticker=`.
- Updated test files (`tests/test_cli.py`, `tests/test_coverage_gaps.py`, `tests/test_integration.py`, `tests/test_resolve.py`, `tests/test_source_coverage.py`) to align with version 0.2.0.
- Updated example scripts (`examples/demo_resolve.py`, `examples/lookup.py`) to the new interfaces.
- Ran all tests (`uv run pytest`) multiple times to ensure stability.
- Removed `--ticker` backward compatibility to strictly enforce `--symbol` according to the new models.

## 3. Decisions Made

| Decision | Rationale |
|----------|-----------|
| Add `--symbol` alias | Improves CLI ergonomics for users who prefer standard financial terms. |
| Retain `--ticker` alias (initially) | Ensure backward compatibility with existing scripts. |
| Migrate to `pydantic-market-data` 0.2.0 | Keep the project aligned with its dependencies and industry standards. |
| Remove `--ticker` entirely | The user explicitly requested to drop backward compatibility, enforcing the new standard `Symbol` strictly. |

## 4. Decisions Refused / Alternatives Rejected

| Rejected Approach | Reason |
|-------------------|--------|
| Keeping duplicate `symbol` and `ticker` properties | Unnecessarily complex and violates DRY principles. Replaced with Pydantic `AliasChoices`. |
| Retaining backward compatibility after migration | User explicitly requested its removal. |
